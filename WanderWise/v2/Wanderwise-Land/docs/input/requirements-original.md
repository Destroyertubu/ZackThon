### 1.3 术语与规则强度


&#x20;               ● **必须**：对应版本的验收要求；违反则该需求未完成。


&#x20;               ● **建议默认值**：可配置工程参数，首次联调和设备实测后统一修订。


&#x20;               ● **待确认**：资料或团队信息不足；不以猜测补齐外部协议。


&#x20;               ● **话题 Topic**：跨旅程复用的语义实体；**世界节点 WorldNode**：话题在某张地图中的实例。


&#x20;               ● **内容 Content**：知乎回答、文章或赛事故事／知识；**摘录 Excerpt**：有来源定位的片段或明确标注的 AI 概括。


&#x20;               ● **场域 Field**：某篇内容的空间结构视图；**旅程 Journey**：一次可暂停、继续、归档的探索。


&#x20;               ● **行囊**：统一收藏库的旅途视图；**收纳柜**：同一收藏库的长期分类视图，不复制成第二套库存。


&#x20;               ● **锚点 Anchor**：用户在话题或内容语境中留下的思考；**洞察 Insight**：合成台产生且由用户保存的关联解释。

## 2. 产品定义与目标用户

### 2.1 一句话定义

**漫知录 · Wanderwise 是以知乎内容为知识来源、以第三人称空间探索为入口、以个人精神家园为沉淀场所的认知旅行 Web 应用。**

用户带着一个问题出发，在不断展开的语义世界中选择方向，遇见观点、深入文章、收集片段、留下思考，最后回家整理知识和生成新的洞察；后续版本让用户通过公开的思考和探索路径遇见同频者。

### 4.2 核心流程

### flowchart TD     A[访问网页] --> B[游客开始 / 继续旅程]     B --> C[温暖小屋]     C --> D[大门：输入问题或随机出发]     D --> E[准备内容与生成世界]     E --> F[第三人称探索话题]     F --> G[观点浮现与阅读]     G --> H[E 收集 / R 留下锚点]     G --> I[F 进入文章场域]     I --> F     F --> J[V 导航与新分支展开]     J --> F     H --> K[保存并回家]     K --> L[收纳柜整理]     L --> M[合成台生成并保存洞察]     M --> N[日志回看旅途星图]     N --> C     N -. ### 5.2 第三人称与物理默认值


&#x20;               ● 角色使用胶囊碰撞体和简化人形／披风轮廓；必须具备 idle、walk、jump 三种可辨识状态，首版不依赖高精度骨骼动画。

&#x20;               ● 相机围绕角色肩部目标点旋转，默认跟随距离 4 米，俯仰角建议限制在 -60° 至 70°；可关闭镜头晃动。


&#x20;               ● 相机从角色目标点到理想位置做障碍探测，遇到墙体缩短距离，离开后平滑恢复。射线忽略角色自身模型。


&#x20;               ● 漂浮岛之间必须存在有碰撞体的桥、坡道或显式传送装置；可见知识连线不自动等于可行走道路。


&#x20;               ● 掉出世界边界后回到最近安全落点；收藏与锚点不丢失。场景加载失败时返回小屋。

### 6.1 WW-01：入口、会话与设置

**页面内容**：品牌名称、简短定位、开始／继续按钮、设备提示、声音开关与素材来源入口。进入后建立匿名随机用户标识及服务端会话，不要求访客输入 Access Secret。

### 6.3 WW-03：种子输入与起程


&#x20;           1. 
&#x20;   问题输入框允许 2–100 个 Unicode 字符，去首尾空白；支持中文标点。超过上限时就地提示，不自动静默截断。

&#x20;   空输入不向搜索接口发送空 Query；用户选择“随心出发”后，从已准备且内容有效的种子池随机选取问题。


&#x20;           3. 
&#x20;   同一问题可拥有不同地图实例：保留输入问题 seedText，另存数值 layoutSeed、内容快照版本和算法版本，区分“重新出发”与“继续原旅程”。


&#x20;           4.

### 6.4 WW-04／05：语义世界与动态生长

**空间层级**：种子中心区 → 一级话题群岛 → 邻近子话题 → 摘录／锚点。地貌由主题类别映射模板，如森林、雪原、草原、湖面石径、城市剪影、乡村小路、观星台，不为每个话题在线生成 3D 模型。

**建议规模**：初始目标 6–8 个有证据的话题；资料较少时允许 3–5 个并说明。每次扩展目标 3–5 个新节点，上限 6 个；去重后可以为 0。P0 单世界最多 50 个话题节点，达到上限后显示“本次旅程的边界已展开，可换个问题再出发”。

**扩展触发**：进入未扩展话题的预取半径（建议 18 米）并停留 800ms 后发起一次请求；同一世界同一节点同一版本只允许一个在途任务。失败后保留已加载世界，用户可显式重试。

**地图稳定性**：新增节点只能占用未使用位置，已访问节点及道路不移动；新增部分经过渐入动画出现。扩展结果必须同时包含语义连线和可通行连接，前端验证端点存在后再提交到场景。

**信息多样性**：有来源支持时，分支至少覆盖相关深化与跨领域关联两类；有不同观点时保留差异。不能为凑多样性编造对立内容。

### 6.7 WW-07：知识行囊

**收集对象**：话题、内容、摘录、自己保存的洞察；锚点推荐收藏可在 P1 扩展。所有条目保留原始对象 ID、来源与本次收集旅程。

**E 收集状态**：未收录 → 待保存 → 已收录。可先播放文字收拢与微光飞入行囊的动画，但持久化失败必须显示“未保存，可重试”，不能保留虚假的成功计数。相同用户对同一对象仅一份有效收藏；重复 E 提示“已在行囊中”。

**B 面板**：顶部显示“本次收获／全部收获”，提供话题筛选、关键词搜索和最近收藏排序。列表展示类型、短内容、作者、标签、来源、备注和保存状态。移除仅删除个人收藏关系，不删除知乎内容；关联连线失效前提示受影响数量。

### 6.8 WW-08：私人想法锚点

R 默认绑定当前命中内容；无命中但位于话题区时绑定当前话题。未进入任何话题区时不允许无语境放置，提示先靠近一个话题。编辑器显示绑定语境、正文、可见范围及保存按钮。

正文 1–500 字；草稿保存在本地；P0 仅私人，P1 才开放“公开”选项。保存成功后在附近安全地面长出光锚，远处只显示微光，近处显示短句。位置记录为话题节点的局部偏移，避免跨地图坐标失效。

同一用户同一话题可有多个锚点。支持在 T 面板和日志中编辑／删除；编辑采用版本校验，冲突时展示服务端内容并保留本地草稿，不自动覆盖。删除后场景与日志同步移除；取消删除不产生副作用。

### 6.9 WW-09：V键追踪

V 对准可见话题后锁定目标。第一态：词云微尘和字符碎屑朝目标方向流动；第二态：文字光带沿可通行路径增强引导；第三态：关闭。若改瞄另一个话题并按 V，则切换目标并从微风态开始。

导航路径基于可通行图求取，不能穿过无桥的虚空或墙体。接近目标约 6 米后光带淡出，最后一步由用户自主寻找；HUD 不设置常驻方向箭头，可显示目标名称与取消按钮。低画质／减少动态效果模式用静态分段光路代替粒子。

不替用户自动移动。目标被卸载时保留轻量位置数据；目标失效时取消追踪并说明。导航不得触发逐帧网络请求。

### 6.10 WW-10：旅程存档与个人画布

旅程状态为 active、paused、completed。暂停菜单提供“保存并回家”和“结束并归档”：前者允许继续，后者完成本次旅程并生成摘要。保存失败时提供重试和“保留本机待同步后回家”，不得伪称云端已保存。

**记录内容**：访问话题、有效停留、阅读、进入场域、收集、锚点、手动连线、扩展、合成及返回家园。不逐帧上传轨迹；坐标用于定期安全点存档，语义事件用于画布。

**自动保存**：每 10 秒、关键写操作成功后、场景切换前保存；本地未确认事件每 5 秒批量发送，失焦前尽力发送，不能依赖 beforeunload 必定送达。

**星图编码**：颜色表示话题类别，节点大小表示去重访问次数，亮度表示上限截断后的有效停留时长，路径粗细表示往返次数；提供图例。点击节点可查看相关收获和锚点；时间轴按语义访问步骤播放，不承诺完整动作录像。

**日志字段**：起始问题、开始／结束时间、访问话题数、收藏数、锚点数、洞察数、保存状态。允许用户删除私人旅程；删除前说明收藏默认保留，旅程关联解除。

### 6.11 WW-11：想法收纳柜

回家即显示行囊中已保存的收藏，按主题标签自动分组。自动归类基于已生成的话题和标签，未知类归入“待整理”；用户可改标签、写备注、搜索和移除。用户手工标签优先，后续 AI 不覆盖。

不存在“把行囊物品搬走”的库存变化；本次旅程筛选保留，收藏的多话题归属也保留。选中 2–4 个条目可直接送往思维合成台。

### 6.12 WW-12：思维合成台

**输入**：2–4 个用户拥有的有效收藏、可选问题（≤ 200 字）。话题收藏本身没有证据片段时，先让用户选择对应的内容／摘录，不能只凭两个词假装形成有来源的合成。

**输出结构**：标题、核心洞察（建议 80–200 字）、联系说明、保留的差异／不确定性、1–3 个可继续探索的问题、实际引用的材料列表。默认明确显示“AI 生成洞察，可编辑”。输出不得将多个作者观点合并后归给某位原作者。

**流程**：选材 → 检查来源 → 生成任务 → 展示结果 → 用户保存。AI 失败时保留材料组合与手工连线，允许写自己的理解；不能用固定文案冒充实时生成。用户保存前，结果为暂存草稿；保存后进入日志和收纳柜，可追加个人备注。

**去重**：按用户、排序后的材料及版本、用户问题、提示词版本缓存。再次点击默认返回同任务／同结果；“重新生成”是明确的新尝试，需要受额度控制。

### 7.2 P2：共鸣值与连鸣

将普通阅读的“+1 共鸣值”作为后台阅读贡献，将主动共鸣／连鸣作为用户表达，两者在界面分别说明，避免用户被自动代表态度。


&#x20;               ● 有效阅读：已展开锚点且前台可见累计 ≥ 5 秒；同一读者对同一锚点每日计 1 次，不计作者自身及已识别异常流量。


&#x20;               ● 连鸣：长按 600ms 后进入连续共鸣，每次操作加 1，**每用户每锚点累计最多 3 次**，服务端唯一约束及上限校验；提供键盘按钮等价操作。


&#x20;               ● 初始实验公式：共鸣值 = 去重有效阅读数 + 基础共鸣数 × 2 + 连鸣次数 × 3。这是项目规则，可调整；不能声称是知乎官方机制。


&#x20;               ● 分发使用截断／对数缩放后的共鸣值，并混入新内容，不直接按无限累加值排序。


&#x20;               ● 站内通知可写“有位同路人在‘伦理学’与你产生了共鸣”；每日合并通知，不自动站外推送。


&#x20;               ● 不同意见可通过另设锚点关联原话题来表达；评论仍可讨论，但不得把“没有踩按钮”等同于禁止不同意见。

### 7.3 P1：同频电话亭

**前置条件**：用户主动开启“允许用公开旅程发现同频者”，并至少公开一条包含 3 个不同话题、5 个有效行为的旅程。人数或数据不足时显示“还需要更多公开旅程”，不展示随机百分比。

**匹配输入**：仅公开且参与匹配的已访问话题、主动公开的收藏关联和连线；不上传私人锚点正文用于匹配，不使用私信内容。默认所有收藏仍为私人；旅程公开并不自动公开收藏全文。

P1 可以先用主题加权 Jaccard，相比依赖 Embedding 更易解释：访问权重 1、阅读权重 2、收集权重 3、主动连线权重 4，每主题总权重截断到 10。两人得分为各主题最小权重之和除以最大权重之和；分母为 0 时不匹配。后续可加入向量相似度，但更改后需记录模型版本。

匹配结果最多显示 3 人，给出共同话题、至少一条交叉路线和对方选择公开的信息。分数如展示为百分比，标签必须是“本次公开探索相似度”，不得表述为心理／人格契合度。

支持查看公开旅程、发起连接申请、接受／拒绝、取消申请、解除连接与屏蔽。连接申请仅带一段可选留言（≤ 200 字）；P1 不承诺即时聊天。服务端唯一约束避免重复申请，拒绝后默认 7 天内不能再次申请。

### 7.4 P2：聊天通道

仅双方已接受连接且未相互屏蔽时开放。首版聊天只支持纯文本（1–1000 字）、游标历史、发送中／已发送／失败状态和显式重试，不支持附件与群直播。

clientMessageId 用于幂等去重；服务端序号用于排序；断线后按序号拉取缺失消息。对方解除连接后禁止新消息，历史按既定删除规则处理。必须有屏蔽、举报和会话删除入口；是否使用 WebSocket 是实现选择，不影响权限与存储规则。

### 7.5 P2：公共行囊与同行团


&#x20;               ● 同行团规模 3–8 人；创建时可处于 1–2 人“筹备中”，3 人起显示已成团，8 人封顶。


&#x20;               ● 邀请需被邀请者接受；团主可移除成员并转让团主，成员可退出。最后一人退出解散。


&#x20;               ● 成员共享收藏的**副本引用**；取用复制到个人行囊，原收藏和公共条目保持，不存在拿空库存。


&#x20;               ● 同一成员共享同一来源对象只产生一个公共条目；成员可撤回自己的共享。源作者收回公开锚点时，其正文不继续通过公共行囊泄露。


&#x20;               ● 加入提示“前辈留了 3 句入门金句”仅在实际至少有 3 条可用推荐时展示，数量来自真实数据。


&#x20;               ● 外部源内容下架时标记不可用；已有个人思考和来源标识保留，不能展示已撤回的私人正文。

### 7.6 P1／P2：漫知图鉴

P1 将话题记录为 unseen、glimpsed、collected。有效靠近并前台停留 ≥ 2 秒才算瞥见；E 才算收录。瞥见显示灰色轮廓与已实际获得的信息，收录解锁彩色条目与完整的可用摘录详情，不额外解锁平台未授权正文。

只对主题活动等固定 catalogVersion 展示 已收录数 / 目录总数。普通动态世界显示“本次发现 N 个话题”。P2 分类集齐可发放装饰皮肤与博识徽章，按用户与目录版本幂等授予，不增加知识分发权力。

### 7.7 P1／P2：词云小径与足迹叠加

三种视图：我的足迹（P0）、同频人的公开足迹（P1）、全员热门小径（P2）。跨世界按规范化 topicId 聚合边，投影到当前地图；不同人的随机地理坐标不能直接叠加。

全员小径使用参与统计的公开轨迹，按用户对话题对的有效穿越次数去重，单人每日单边贡献最多 3 次。只有至少 5 名不同用户贡献才显示汇总热度；无人达到门槛时显示空态。热度用亮度和宽度表达，并标明统计周期，不伪称完整知乎用户群体的阅读路径。

### 7.8 P1／P2：每日热点与双周主题

每日热点：服务端统一缓存热榜，用户选择热点标题后作为种子，进入常规搜索与世界生成流程。展示更新日期和“知乎热榜话题”来源；热榜只表明热度，正文观点需继续检索。不可用时展示最后更新时间或切换“推荐路线”。

双周主题：运营维护 title、介绍、起止时间、精选内容、固定目录、地图风格和奖励。以配置驱动，不要求 AI 定期全自动策展。活动结束后仍可回顾已保存旅程；素材或来源不可用时按内容失效规则处理。

### 8.4 Blender 到 Web 的约束


&#x20;               ● 输出 GLB／glTF；Web 统一采用右手坐标、Y 向上、1 单位 = 1 米。Blender 导出后以测试方块验证轴向与比例。

&#x20;               ● 每个纹理默认 ≤ 1024²，少数关键材质可 2048²；首版优先一种已验证压缩链路，不同时引入所有解码器。

&#x20;               ● 建立 ASSET\_LICENSES.md，逐项记载来源、作者、许可证、署名文字与使用文件。第三方素材的许可按具体资产页面核验；不得把参考站截图作为可自由复用素材。

### 9.4 语义关系与布局

P0 可采用 LLM 提取关系加规则布局；Embedding 作为可替换的 SemanticProvider，不能因为缺少向量服务而阻塞全部世界。已接入 Embedding 时先同版本向量化、计算相似度、构建近邻图，再添加有依据的跨域边；相似度不等于事实关系或认同程度。

布局默认在 X–Z 平面生成主要可行走区域，Y 只作少量信息层级和地貌变化。节点最小间距建议 16 米、中心半径建议 25–45 米，结合角色速度调整。先聚类和排布，再冻结；浏览器中不持续运行力导向模拟。

必须满足：节点之间可达、出生点安全、主要文字不被建筑遮挡、扩展不侵入已访问区域、同快照重复打开坐标一致。确定性以保存的 layoutSeed + layoutVersion + sourceSnapshotSetId + 节点布局结果 为准；sourceSnapshotSetId 标识参与该世界版本生成的一组内容快照，而非单篇正文。同一句问题重新调用 LLM 不保证生成相同世界。

### 10.4 OAuth 与身份待确认边界

黑客松 App ID／App Key 在赛事项目创建后发放；Access Secret 另行申请。P0 的在线游客路线不等待 OAuth 凭证。依据 S02，项目创建入口在提交窗口开放，必须预留 P1 OAuth 的后期接入时间。

浏览器访问 Wanderwise 登录入口 → 后端创建一次性登录事务并跳转知乎授权页 → 用户本人确认授权 → 后端接收 authorization\_code（兼容 code） → POST 表单交换 access\_token → 使用已确认的身份接口建立本地身份映射 → 签发 Wanderwise 自有会话 Cookie → 跳转回原页面，不把知乎 Token 交给浏览器 授权地址：https\://openapi.zhihu.com/authorize，参数为 redirect\_uri、app\_id、response\_type=code，可发送随机 state。

Token 地址：POST https\://openapi.zhihu.com/access\_token，表单包含 app\_id、app\_key、grant\_type=authorization\_code、redirect\_uri、code=<回调 authorization\_code>。优先检查 access\_token，按 expires\_in 管理过期；业务 code: 20000 可能表示成功，不能误判。

**上线前必须关闭的协议缺口**：S04 允许发送 state，但未明确保证回传；S07 记录过不回传 state 的实测。需要在比赛项目实际验证关联性校验方案，不能把“请求里带了 state”当作已完成登录 CSRF 防护。S04／S06 没有闭合稳定用户 ID、昵称／头像获取 endpoint 和 schema，也不能猜造 /user 契约或用 Token 哈希冒充稳定账号。未确认时保持游客版，不开放依赖可靠账号的公开写操作与跨设备迁移。

资料未定义 refresh token、scope、撤销端点及完整拒绝授权协议；过期后重新发起授权，取消／失败后返回原页面。Token 失效时绝不回退到 Access Secret 所属开发者账号读取数据。

### 10.5 授权用户数据

代表授权用户请求 S06 中的创作、关注、收藏时，除了 Access Secret 和时间戳，还必须携带 X-OAuth-Token。CLI 不能代替这一浏览器多用户流程。

导入收藏属于 P1 可选入口：用户点击后选择范围，首批 ≤ 20 条，明确展示导入内容并确认添加。Summary 仍是摘要，recent 只代表近期收藏；不得承诺可读取所有历史／私密收藏。分页严格跟随 Paging.NextOffset，没有 Paging 的接口不自行推算下一页。

&#x20;               ● 应用时间使用带时区 ISO 8601 UTC，显示按用户本地时区；上游 Unix 秒在适配层转化。


&#x20;               ● 坐标单位为米：{x, y, z}；旋转角单位为弧度。坐标只对指定世界版本有意义。


&#x20;               ● 可见性枚举：private | public；团内可见使用独立成员权限，不混入公共读接口。


&#x20;               ● 可变记录有 version、createdAt、updatedAt；内容快照、世界布局与已归档事件尽量不可变。

### 12.5 公开、迁移与删除


&#x20;               ● P1 分享生成专门的公开快照，只包含用户确认的话题路径和选中的公开锚点；排除私人备注、精细停留时间和未公开内容。分享撤销后 Token 失效。


&#x20;               ● P1 游客迁移仅在稳定知乎用户身份得到验证后执行事务：收藏按目标去重，旅程和锚点保持原始 ID，冲突备注保留两版供用户处理；迁移成功才撤销旧游客会话。


&#x20;               ● 删除旅程默认保留收藏和锚点，清空其旅程关联；删除旅程事件、检查点及公开快照。用户明确选中“一并删除本次私人锚点”时才级联删除。


&#x20;               ● 删除收藏删除其手动连线；已保存洞察保留当时材料引用快照，来源失效则标明。删除锚点后相关公开展示和通知正文同步失效。


&#x20;               ● 洞察作为后续合成材料时始终标明其 AI／用户创作属性，并沿材料引用追溯原始证据；不得把前次生成文本重新标注为知乎原话。引用链不闭合或源内容不再允许使用时提示重新选材。


&#x20;               ● 用户可清除自己的全部应用数据；公共内容缓存不等于用户数据，可按来源策略独立到期。


&#x20;               ● 建议保留期：原始运维日志 7 天、未保存 AI 草稿 24 小时、已确认幂等结果 24 小时、游客无活动数据 30 天；用户保存的数据保留到删除。到期删除私人数据的后台任务与前端提示必须一致，团队可在上线前统一调整。

## 13. 应用 API 契约

### 13.1 公共约定

以下均为 **Wanderwise 自有 API**，基础路径 /api/v1，不是知乎官方端点。使用同源 HttpOnly 会话 Cookie；写操作校验 Origin 和 CSRF Token，所有用户标识由服务端会话取得，不接受前端 userId 指定所有者。

成功响应：{ data, meta: { requestId, dataMode?, sourceFetchedAt? } }；失败响应：{ error: { code, message, retryable, details? }, meta: { requestId } }。无敏感信息的 details 可含字段校验失败或上游 HTTP 状态，不包含完整请求头、Token 或上游堆栈。

需要生成的操作返回 202 和 jobId；已命中可用缓存可返回 200 和结果引用。创建旅程、生成任务、收藏、锚点、保存洞察均使用 Idempotency-Key；同键不同请求内容返回 409。明确 PUT／DELETE 操作应天然幂等。

分页统一 cursor（不透明字符串）、limit（默认 20，最大 50），返回 items/nextCursor/hasMore。前端不能把本 API 的分页参数直接传给知乎上游。

## 15. 数据安全与内容归属

### 15.1 身份与访问控制

会话 Cookie 使用 HttpOnly、Secure、合适的 SameSite 设置，登录后轮换会话；跨站 OAuth 回调的 Cookie 行为需真实浏览器验证。退出清除服务端会话及 OAuth Token。OAuth 会话默认不持久化到不受控磁盘。

所有私人资源查询和修改都按当前用户过滤；不能仅靠不可猜的 URL 代替权限校验。世界 ID、任务 ID、场域引用、收藏 ID 等都做所有权或合法公共引用校验。公开读接口输出字段白名单。

公开生成服务实施会话／IP／全局预算限制，首次建议每会话每小时创建世界 ≤ 10 次、合成 ≤ 10 次，具体由实际额度配置；多人共用网络不能只靠 IP 作为用户身份。管理员入口采用独立身份鉴权，不通过一个前端隐藏按钮保护。

### 15.2 内容来源和归属

原文、摘要片段、用户锚点和 AI 洞察具备不同的视觉标签及数据类型。每条外部摘录保留作者、内容归属、实际来源和获取时间；页面支持“查看来源”。外部作品能被读取不等于已获得无限再分发许可。

只在完成阅读、导览和用户收藏所需范围内展示／缓存材料，不提供整库导出或批量下载。官方允许范围不明确的正文长期保存、二次公开分享和改编，在对应功能上线前确认；P0 只实现必要展示及受控缓存，内容失效可撤下。

站内锚点、共鸣、评论和聊天明示属于 Wanderwise，不能制造已发布到知乎的反馈；没有用户主动确认，不自动对外发布私人思考。

### 15.3 外部输入和 AI

所有正文、头像 URL、链接、标签和用户文本均视为外部输入。DOM 不直接注入未净化 HTML；禁止 javascript: 等危险链接协议，服务端只代理固定提供器地址，避免用户输入 URL 引发任意抓取。

LLM 不接触凭证；系统提示、正文证据、用户问题分开组织。输出只允许受控 schema 和已有证据 ID；不得用模型返回的文件路径或网址控制后台读写。日志不记录私人锚点、完整搜索问题或 OAuth 回调查询串。

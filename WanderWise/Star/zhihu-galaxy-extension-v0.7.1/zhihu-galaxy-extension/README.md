# 知乎问题星系 · Zhihu Galaxy v0.7.0

三维词云星系、空间全息原文、可调力布局、自定义配色，以及可选的两阶段 AI 关键词校对。保留 v0.6 的知识行囊、原文选段、笔记、标签、复习状态、导入导出与探索航迹。本包可直接加载，不需要 npm、构建步骤或 CDN。

## 安装与更新

1. **更新前先从知识行囊导出 JSON 备份。** 将本包内 `zhihu-galaxy-extension` 的内容覆盖到此前加载的同一个扩展目录；不要先卸载旧扩展。随后在扩展管理页点击“重新加载”，再刷新已打开的知乎页面。
2. 首次安装：Chrome 打开 `chrome://extensions/`，Edge 打开 `edge://extensions/`，开启开发者模式，选择“加载已解压的扩展程序”，选择包含 `manifest.json` 的目录。
3. 打开知乎问题页面，从页面的星系按钮或扩展图标进入。在非知乎页面点击扩展图标，会打开随包演示页。

演示页全部使用**合成回答**，不是抓取成果。普通网页演示不允许配置云端密钥；AI 接入需要以扩展形式加载。正式知乎读取依赖页面可见数据、登录状态与接口可用性，不保证获取问题下的所有回答；本次读取上限仍为 500。

**使用旧版 bridge 的用户：关闭旧进程，改用本包的 bridge 后重启。** v0.7 不会把回答发给缺少新版握手信息的旧 bridge，避免旧版自动触发另一套远程语义提炼。

## 三维不是屏幕上的排版

`spatial.js` 为每个节点维护真正的 XYZ 位置，`galaxy3d.js` 用同一台透视相机投影节点、连边和全息平面。已移除 v0.6 的屏幕空间节点排斥和摘要卡片自动寻找空白位置：旋转时有视差，靠近时有尺寸变化，节点不会为了排版而被偷偷搬到别的屏幕位置。

实现采用 **Canvas 2D 承载三维透视投影 + CSS matrix3d 原文平面**，不是 WebGL 网格引擎，也不包含未声明的 Three.js 依赖。回答选段挂在该节点上方的世界坐标中，略微朝向相机，带静态扫描线与边角光标；前方的星球可遮挡后方的全息面板。过远、镜头背面、超出视野或相互遮挡的次要面板会隐藏，不会在屏幕上随意避让。

这意味着不承诺任意角度下都完全不重叠。拥挤时可以旋转、平移、调大斥力、减小节点，或从主题目录/搜索直接进入。需要长时间稳定阅读时，启用可选“固定阅读窗”，或在右侧原文面板阅读。

## 调校空间

星系 → 设置 → 空间。滑杆即时预览，点击“应用并保存”持久化；关闭 × 撤销未保存的参数预览，不撤销已经执行的 AI 修正。

| 参数 | 范围 | 含义 |
|---|---:|---|
| 节点引力 | 0–3，默认 1 | 连边上的弹簧拉力，0 关闭该分量 |
| 节点斥力 | 0–4，默认 1.35 | 三维近邻排斥，值越大越疏 |
| 全部节点尺寸 | 0.4–2.5 | 所有节点的世界尺寸倍率 |
| 回答 / 主题大小比 | 0.4–2.5 | 额外调整回答节点大小，主题不随之改变 |
| 角度旋转速度 | 0.1–3 | 鼠标拖拽和 WASD 的共同倍率 |
| 滚轮缩放速度 | 0.2–2.5 | 调整前后观测距离的速度 |
| 同时出现的选段 | 1–8，默认 4 | 全息面板显示预算，不是全部回答节点数量 |
| 选段空间尺寸 / 不透明度 | 0.65–1.7 / 0.35–1 | 调整世界中的全息平面 |

引力和斥力是图布局系数，不是牛顿物理常数；关闭二者后，仍保留弱锚定、核心径向约束和空间边界，避免节点漂走。力布局采用近邻空间哈希与稀疏连边，运行有限步后休眠；“冻结空间”随时停止布局，旋转缩放仍可使用。“重新舒展”在当前位置继续迭代，不删除节点。

鼠标拖拽 / WASD 旋转；Shift + 拖拽或中键拖拽平移；滚轮前后观测；右侧滑杆上远下近；返回恢复此前视野。没有自动旋转或转向惯性。舒适模式背景静止；探索模式背景星点也参与透视；静读模式锁定转向，但不是切回二维。系统要求减少动态效果时，关闭对应相机补间，布局不以持续漂移呈现。

## 配色

设置 → 配色：**深空科技**（深黑、蓝紫青）、**日落潮汐**（橙、砖红、青绿）、**雾色花园**（低饱和莫兰迪）。可分别修改背景、星云、主题、交汇观点、回答/全息、正文、轨迹七种颜色，并调节光晕和背景星点密度。

改色后自动转入自定义；应用后本地保存。可导出和导入配色 JSON。正文颜色与背景对比过低时会被自动修正，界面会提示；这不是对每个细小标签和半透明叠加状态的完整无障碍认证。

## AI 接入

设置 → AI 校对 → **供应商与 API Key 设置**，进入扩展自己的独立设置页。供应商可选 DeepSeek、OpenAI、阿里云百炼/通义千问，以及自定义 OpenAI-compatible 服务。

填写 Base URL、账户可用的准确模型 ID 和 API Key，勾选原文选段发送授权及“启用 AI”，点击“保存并授权此域名”。保存后可先“测试已保存的配置”，再回到星系点击“刷新连接状态”和“校对当前关键词”。测试连接同样会消耗少量 API 额度。Base URL 填供应商给出的基础地址，不重复追加 `/chat/completions`。

供应商预设不是账户权限保证；模型 ID 可以更换。百炼端点需要与密钥地域/业务空间匹配，请从控制台复制，不要直接使用带 `{WorkspaceId}` 的模板。自定义服务必须兼容 Chat Completions；并不直接适配 Anthropic 原生 Messages、Gemini 原生协议或 Azure 专属鉴权。云端只支持 HTTPS；本地服务可用 `http://127.0.0.1:端口/v1` 或 localhost。

### 一轮校对的实际流程

1. **扫描标签**：一次请求查看最多 80 个现有主题/观点，每个附至多两条短支持句。只允许修复明显的网页噪音、代词、套话或断句残片，每轮最多 8 个词；合理标签不重写。
2. **本地召回**：分词、汉字二元组与倒排表做宽松匹配。默认门槛 0.10；每个修正词最多发送 12 篇候选，可调为 8–24。候选先过相似度门槛，再按全局“最多赞 / 最新 / 随机”排序，每篇只提供至多两条短原文。
3. **批量复核**：所有修正词的候选合在第二次请求中，模型每组最多选 8 篇，指定原文句索引。不要求凑满，不允许生成或改写摘录。
4. **校验与提交**：验证节点 ID、候选范围、文字长度、去重和原文子串。没有原文证据就不改名；有证据才更新标签、邻接和局部布局。所有回答节点及收藏 ID 保留。未选入的回答不删除，可归到其他本地主题或问题核心。

通常一轮最多 **两次 API 请求**，不是每篇回答一次；扫描无必要修改时只有一次。本地结果先展示，AI 不阻塞进入星系。可选回答池稳定后自动校对一次；默认关闭自动和 AI。断网、超时、输出格式错误等不提交本轮修正，不自动重试付费请求。可取消、查看修改依据并撤销最近一轮。图版本变化、切换优先级或关闭星系会作废仍在等待的结果。

**“每组最多 8 篇”与“画面最多 8 张全息面板”是两个独立限制。** 未入选仍不影响全部回答的存在和检索。随机顺序使用固定种子，加载、列表、候选及最终精选共用；随机仅针对已取得的回答池，不等于从整个知乎问题均匀抽样。

AI 也可能判断错误；本地词面相似度无法穷尽同义改写。校对不是人工审核替代品，保留原文、审计记录和撤销是为便于检查。详细协议与修改入口见 `docs/AI_MODULE.md`。

## 数据与密钥

轨迹/收藏保存在本机 `chrome.storage.local`，包含原文选段和来源。默认 API Key 仅存浏览器会话；主动勾选“在本机记住”时存扩展来源私有 IndexedDB，不写进知乎文档、不回填到设置表单、不随行囊或配色导出。每个密钥绑定到确切 Base URL，切换地址不会直接带过去。长期本地保存不是加密保险箱，公开多用户部署应改用后端密钥代理。

云端校对有独立 opt-in 授权，只发送标题、词语和少量回答原文。不会加入作者字段、来源网址、笔记、收藏状态、轨迹或画像；**选段本身仍可能包含个人信息**。保留的本地 bridge 仅用于补充数据，本版扩展不会授权它执行旧的整批语义提炼。

画像与相似用户仍未实现：`getProfileInput()` 返回 `not_implemented`，不推断性格、不生成向量、不上传轨迹。补上了 `schemas/profile-input.schema.json` 以及未来观测项定义。旧 v1 行囊备份仍可导入。最多保留 5000 条轨迹事件、600 条收藏，收藏达到预算后提示整理，不悄悄删除。

## 可选数据 bridge

没有 bridge 也能使用当前页面/同源接口。需要补充数据时，可在 PowerShell 运行 `powershell -ExecutionPolicy Bypass -File .\backend\start_bridge.ps1`，或在已经配置好 CLI 的环境运行 `python backend/bridge.py`。启动脚本沿用旧包的 CLI 配置流程；数据源的 Access Secret 与这里新接的模型 API Key 是两类不同凭据，不要混填。

bridge 绑定 127.0.0.1:8765。新版提供版本握手，默认不启用历史 zhida 提炼；即使人工设置旧环境变量，来自新版扩展的请求仍显式拒绝旧 AI 路径。重新启动 bridge 才能替换仍在运行的旧进程。数据接口仍为 best-effort，未取得的回答不会伪装成已加载。

## 验证与开发

实际回归：58 项 Node 核心/AI/后台安全与 bridge 握手单元测试通过；离线 Chromium 的 30 项交互检查通过，含 500 回答、12 个视角、真实 XYZ 投影、三套配色、原文选段收藏、航迹、模拟 AI 两阶段修复/回滚。没有未捕获的浏览器 JavaScript 异常。

这些浏览器测试使用合成回答和内存行囊适配器；后台调用使用 mock Chrome/fetch。**不等于在正式知乎登录态、真实扩展存储以及付费供应商 API 上的完整端到端验证。** 包中截图也是合成演示；`ai-audit-mock.png` 中时延是模拟响应，不可用于估计真实模型速度。500 节点绘制耗时是单机离线测量，不是帧率承诺。

运行 `node --test tests/*.test.cjs`；浏览器测试运行 `python tests/browser_regression.py`（需要 Playwright 与 Chromium，可通过 CHROMIUM 指定可执行文件）。日志、报告及截图在 `tests/results`。运行实现无这些测试依赖。协议/schema 文件在 `schemas`，渲染与架构说明在 `docs`。

# 知乎问题星系 · Zhihu Galaxy v0.6.0

把一个知乎问题展开成“问题核心 → 高信息主题 → 交汇观点 → 真实回答”的三维语义星系。

## v0.6.0 使用说明

此压缩包包含上一轮提供的全部 v0.6.0 修改源码、原包图标与本地 bridge，无需逐个下载或手动合并文件。

首次安装：解压后，在浏览器扩展管理页开启「开发者模式」，选择「加载已解压的扩展程序」，加载包含 manifest.json 的 zhihu-galaxy-extension 文件夹。更新已有安装：先导出已有行囊数据备份，将本目录内容覆盖到原来加载的扩展目录，再点击扩展的「重新加载」按钮，并刷新已经打开的知乎页面。不要先卸载旧扩展，以免清除本地数据。

本版重点：独立摘要卡片层与固定阅读卡；三维分散、屏幕投影避让与密集节点候选选择；主题目录、已载入正文搜索及筛选；原文选段收藏、笔记、标签、复习状态与 Markdown / JSON 导出、JSON 合并导入；语义到访航迹与逐站回顾；舒适 / 静读 / 探索模式与低动态视觉。

轨迹和收藏保存在本地，不新增轨迹上传功能。用户画像仅保留代码内数据契约及 getProfileInput() 接口，尚未实现画像推断，也未提供独立 JSON Schema 文件。

验证边界：此前的核心测试日志与离线浏览器报告附于 tests/results；本次打包检查了所有顶层 JavaScript 的语法、manifest / demo 的本地资源引用，以及 ZIP 完整性。未在本次打包中重新执行浏览器交互测试；尚未完成正式知乎登录态、真实分页接口及正式扩展存储的完整端到端验收。演示页面和测试截图使用合成数据。

下文 v0.5 及更早版本的章节作为历史说明保留；与 v0.6.0 不一致的行为以本节及实际代码为准。

## 安装扩展

1. 解压 ZIP。
2. Chrome 打开 `chrome://extensions/`，Edge 打开 `edge://extensions/`。
3. 开启「开发者模式」。
4. 「加载已解压的扩展程序」→ 选择本目录。

扩展没有后端也能基于当前知乎页面工作。为了得到更完整的数据与更好的观点提炼，建议同时启动随包提供的 zhihu-cli bridge。

## 启动 zhihu-cli 数据 bridge

Windows PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\backend\start_bridge.ps1
```

第一次运行时会使用随包附带的官方 `zhihu-cli` Skill 安装兼容 CLI。如果本机还没有配置 Access Secret，会通过不回显的 PowerShell 输入框询问一次，并交给 CLI 的凭据机制。Secret 不写入扩展源码、ZIP、`.env` 或浏览器 storage。

Bridge 监听 `127.0.0.1:8765`。插件后台 Service Worker 与它通信，知乎页面拿不到 Access Secret。

## v0.5：完整回答星系与真正可下钻的层级

- 修复 Web API 过去最多只抓 6 页（约 120 篇）的硬上限；现在会按用户的 `maxAnswers` 持续分页，设置 200 时会尝试抓满 200，最高可配置 500。
- 语义层不再“18 篇样本决定全世界”：zhida 会从高赞头部和长尾回答中最多抽取 48 篇做覆盖式语义编辑，目标 16~24 个主题、24~48 个交汇观点。
- 每篇已载入回答只生成一个绿色 Answer Satellite。回答可与多个语义节点有关联，但不会因为挂在多个现象下面而复制成多个相同绿色点。
- 所有已载入回答都会被分配到最相近的主题或交汇观点；即使当前本地语义暂时为空，也会先围绕问题核心显示回答点，不再出现“载入 118 篇却只有十几个绿色节点”。
- 蓝色主题点击后会直接展开它的紫色子节点和回答簇；右侧相关观点改为可点击按钮，可以继续下钻。
- 高质量语义回来后，已有回答点不会删除或复制，而会平滑漂移到更准确的 refined cluster。
- 进一步过滤 `跟我 / 好的人 / 从来都不是 / 这份 / 的人` 等口语、代词和语法残片；本地主题要求在大样本里具备重复支持，避免一次性句子碎片进入远景。
- 蓝色主题与紫色观点只去除真正同名/几乎同名节点；允许 `校园招聘 → 校园招聘信息差` 这种正确的上下层展开。

## v0.4：主题优先，而不是词频优先

远景蓝色节点从“关键词”升级为“主题节点”。本地 fallback 会更保守地只显示少量高置信概念；zhida 语义提炼不再要求主题名称逐字出现在原回答，而是允许在证据回答支持下压缩成能独立理解的议题标签，例如 `教师认知边界 / 校园社会脱节 / 就业市场变化 / 代际经验失效`。

语义模型被明确要求：仅看 8~12 个主题就应该能复述这个问题在讨论什么；禁止 `评论区 / 脑子里 / 我说 / 不知道 / 是不是 / 老师 / 教授 / 研究生` 这类孤立、口语或角色词。孤立实体只有组合成具体主题后才允许出现。

## v0.4：渐进更新严格只增不减

节点 ID 改为由语义标签稳定生成。每批新回答和最终 zhida 结果到达时，渲染器执行 append-only merge：

- 已经显示过的主题、交汇观点、回答卫星保留原位置；
- 已有节点只更新支持度、回答集合等元数据；
- 新节点淡入；
- 不再因为重新计算 top-k 或从本地语义切换到 zhida 语义而让旧节点消失；
- 为防止无限膨胀，只限制“还能新增多少节点”，绝不会为了腾位置删除已经出现的节点。

## v0.4：回答金句保证可见

回答的第一段第一句继续作为“开篇观点”。除“当前画面可见回答 <= 5”之外，现在还有两条强规则：

- Hover 某个回答时，必定显示它的开篇观点；
- 点击回答时，必定显示；点击交汇观点时，最多显示其附近 5 个回答的开篇观点。

因此不会再出现“已经贴近并选中了回答，却仍看不到金句”的情况。金句改用暖金色浮层，并通过引导线与回答卫星连接。

## v0.3：渐进式加载

上一版会等待 bridge / 语义提炼后再进入星系，因此常出现十几秒等待。v0.3 改为：

1. 先从当前页面 hydration + DOM 中获取已经可用的回答；
2. 默认按赞同数从高到低排序，首批目标为 20 篇；
3. 首批达到阈值即立即放开星系；若当前页面不足阈值，最多只等待约 1.8 秒，就先用已有数据进入；
4. `/api/v4/questions/{qid}/answers` 与 zhihu-cli bridge 继续在后台运行；
5. 新回答到达后，每批默认加入 10 篇，星系在用户漫游过程中重新计算并淡入新的语义节点；
6. bridge 的高质量语义提炼完成后，以只增不减的方式加入高质量主题与观点；已出现节点不会被替换掉或删除。

顶部「⚙ 设置」可以调整：

- 优先顺序：`最多赞 / 最新`；
- 达到多少篇后放开预览；
- 每批新增回答数；
- 一次最多加载多少篇。

设置保存在 `chrome.storage.local`，之后打开其他问题也会继续使用。若在当前星系里提高最大加载量或改变排序方式，插件会立即再次补充数据，而不是要求重新打开页面。

## v0.3：视觉语义编码

不同节点不再全部使用同一颜色：

- 蓝色：高信息主题 Theme Star；
- 紫色：交汇观点 Phenomenon Node；
- 青绿色：真实回答 Answer Satellite；
- 白色 / 蓝色光晕：当前问题核心。

左上角提供固定图例。连线也跟随节点类型使用对应色相，方便远距离判断结构。

## v0.3：回答段首观点浮现

回答是目前最细一级节点。当当前视域中可见的回答卫星数量 `<= 5` 时，插件会直接在每个回答点附近显示：

> 第一段的第一句话

这句话被视为该回答最接近“开篇观点”的轻量摘要。超过 5 个回答点时自动收起，防止形成文字墙。右侧回答详情面板里也会把该句单独强调显示。

## v0.3：缩放轴修正

右侧纵轴现在严格满足：

`上 = 全貌 / 远` → `下 = 深入 / 近`

滚轮也改为常见相机语义：向上滚动拉近、向下滚动拉远。

本轮没有继续扩大最近缩放范围，最低相机半径仍保持上一版数值，避免在没有重新设计近距离节点形态前产生穿模和视觉混乱。

## 数据来源

进入问题后会合并并去重：

1. 当前知乎页面 hydration / initial-state 中严格识别出的 Answer 对象；
2. 当前页面已渲染的真实回答 DOM；
3. 当前登录态下的同源 `/api/v4/questions/{qid}/answers`（best-effort）；
4. 官方 `zhihu-cli search zhihu` / 开放平台搜索结果；
5. 可选 `zhida-fast-1p5` 观点提炼。

按真实回答 ID 优先去重，保留更完整正文版本。排序使用赞同数或回答时间；没有时间字段的数据在“最新”模式下会自然排到后面。

## 交互

- `W/A/S/D`：围绕问题原点飞行；
- 鼠标：点击可见节点；
- 右侧纵轴 / 滚轮：调整观测距离；
- `Esc` / 「返回位置」：精确返回上一个空间状态；
- 「⚙ 设置」：调整渐进加载策略；
- 点击现象节点：查看绑定的真实回答，并跳转知乎原文。

## Bridge 环境变量

- `ZH_GALAXY_SEARCH_PASSES=1..3`：开放平台搜索召回次数；
- `ZH_GALAXY_USE_ZHIDA=0|1`：是否进行知乎直答语义提炼；
- `ZHIHU_CLI=<path>`：显式指定 CLI；
- `ZHIHU_ACCESS_SECRET`：仅适用于进程级 Secret 注入，Bridge 不读取项目 `.env`。

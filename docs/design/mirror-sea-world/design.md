# 漫思 · 镜海群岛

2026-09-13 · 第一轮世界设计提案与效果图。本文描述目标体验；本轮不改动正在运行的场景。

## 设计主张

**小屋整理自己，观星台发起交流，陆地经历问题，星系理解关系。**

四个空间贯穿同一次思想旅行。玩家在小屋整理关心的事，带着材料上观星台，选择走进一个情境或展开一片星系，带回原文、疑问和自己的作品。每个空间都有留下来的理由，也有明确的出发与返回入口。

这延续了上游《设计理念》中的“问题出发—遇见观点—深入文章—收集片段—回家形成洞察”。保留星系的三级纵深；新增的陆地负责有语境、有顺序、有行动的旅行。

## 一、把普通山坡外景改为镜海上的花园世界

小屋落在平缓的珍珠色石台与木质水岸上。门外是镜湖、花林、桥和可行走的庭园，远处才展开淡紫山脉与青碧海域。露台下不再出现大块裸露褐土、干草坡和普通山谷照片。陆地仍有可信的承重、路面和尺度，奇幻感来自水、植物、矿物与光共同形成的景观。

- **延续材质**：深浅有层次的木纹、旧黄铜、奶油色灰泥、亚麻、清透玻璃、常春藤和成熟树木。近景细节沿用小屋与星树花园的标准。
- **重做地貌**：近处是柔和的浅色矿岩、苔藓花床、清澈浅水和木桥；中景是紫冠花林与水面倒影；远景是层叠山体、薄雾和散落海岛。
- **统一色彩**：家园的琥珀暖光作为视觉锚点；森林用翡翠绿与紫罗兰；湖海用青碧与珠白；落日大道用杏金、珊瑚与玫瑰紫；星系保留深靛底色与星光。
- **统一世界时间**：小屋窗外、陆地和观星台共享地平线、日月方向与天气。观星台可在进入观测状态时柔和过渡到星夜，退出后回到世界时间。场景主题可以局部强化色调，但建筑和地貌仍相互认得出来。
- **有节奏的动效**：水面缓慢起伏、树叶微风、零星萤光、玻璃中流动的思想粒子、沿路线前行的微弱光迹。进入阅读时减弱运动，保留安静的文字背景。

不把每个物体都做成发光体。明亮的位置承担引导，阴影和雾气提供距离感；奇幻色彩必须建立在可辨认的材料与光源上。

## 二、四个空间分别承担什么

| 空间 | 核心问题 | 内容 | 主要行动 | 带走什么 |
| --- | --- | --- | --- | --- |
| 小屋：我的思想家园 | 我关心什么？我形成了什么想法？ | 我的兴趣、收藏与关注更新、批注、作品、探索日志、可编辑的兴趣画布 | 整理、重读、比较自己的变化、用个人材料合成新想法 | 一个准备出发的问题或想法 |
| 观星台：思想与外界的窗口 | 我想向外问什么？什么值得回应？ | 待探索的问题、跨领域配方、旅程预览；未来接入的公开路线与回应 | 选择方向、调酒、出发、回顾收获、主动分享 | 一条情境旅程，或一个星系探索起点 |
| 陆地：可经历的知识 | 这个问题放进具体生活，会怎样？ | 情境、案例、实践步骤、不同视角、途中可读的真实帖子 | 行走、选择岔路、观察、比较、完成小任务 | 一段理解过程和自己的创作或判断 |
| 星系：可展开的知识关系 | 问题之间有什么关系？依据在哪里？ | 相关问题或明确标注的主题集合 → 回答/文章 → 原文段落 | 缩放、定位、比较、追溯、收藏和批注 | 有出处的观点、段落和待追问的分支 |

**陆地提供情境与顺序，星系提供关系与尺度。** 同一篇帖子在陆地上可以是一个故事中的停靠点，在星系中仍是有固定身份和出处的文章节点。玩家可从陆地随时选择“在星系中展开”，返回时落在原来的路口。

现有星系的距离、亮度与分布主要服务于相关性与问题归属。没有可验证的关系数据时，不把它们解释为“支持、反驳或因果”；这些关系需要后续明确的引用依据和标注。

### 小屋里的物品分工

- **书架与想法收纳柜**：真正收藏过的帖子、段落与自己的笔记；保留来源和收藏缘由，支持按关注话题整理。
- **窗边阅读位**：正在读的文章、上次停留的位置，安静阅读与批注。
- **兴趣画布**：自己选定的兴趣、提出过的问题、近期作品及探索变化。可以修改、隐藏和纠正；不自动给玩家下性格结论。
- **思维合成台**：把两件个人收获放在一起，加入自己的意图，得到一个有依据的新问题、假设或创作提纲。玩家编辑与采纳后才成为自己的作品。
- **日志与旅行纪念**：保存路线、途中改变的判断、写下的文字或拍摄的作品；纪念物可重新打开那次旅程。
- **更新匣与同频电话亭**：更新匣承接站内关注内容；第三方关注同步、人与人的联系依赖未来真正接入的账户与服务。效果图中的物件不代表已接通这些能力。

### 两处合成各做一件事

**小屋合成台产出想法；观星台调酒台把想法变成出发方式。** 两者可以共用检索与模型服务，但输入侧重点和结果不同。

例如，小屋里把两条批注合成“空镜头能否像小说的留白一样表达离别”；拿到观星台，再加入摄影材料，就能调出一条围绕这个问题展开的落日大道。也允许在观星台直接选两个话题即刻体验，不强迫完成前置流程。

## 三、森林、山川、湖海的意义

地貌对应探索方式；一个领域可以经过多种地貌。文学不必永远在森林，科学也不必总在山顶。

| 地貌 | 适合承载的知识关系 | 玩家体验 | 有意义的布景 |
| --- | --- | --- | --- |
| 森林：分岔与相遇 | 一个兴趣周围的相关问题、不同案例与相邻领域 | 顺着兴趣走；在路口了解关联原因，再主动选方向 | 岔路、树洞、林间开阔地、树根间的阅读座；每处少量内容 |
| 山川：循序深入 | 有前置条件的概念、方法与实践路线 | 从能理解的起点逐级深入，途中有休息与旁支 | 山径、台阶、桥、观景平台；高度表示路线进度，不表示观点优劣 |
| 湖泊：停留与反思 | 围绕同一问题的两三种解释、旧判断与新判断 | 并置阅读，记下自己同意和仍不确定的部分 | 对岸阅读位、倒影、安静岸台；让对照材料有清楚出处 |
| 海岸与远海：跨出熟悉领域 | 已有兴趣与陌生主题之间的联系 | 从熟悉的岸出发，自己决定想走多远、接受多少意外 | 码头、灯塔、舟与岛屿；显示目的地与关联理由 |

远处首先看到的是目的地轮廓与少量路标，走近才看到标题，选择后再出现正文阅读层。不要把所有文章同时挂在空中，也不要把山林变成沿路摆满桌子的展销会。

## 四、每一杯酒，都通往对应的场景

用户明确的核心交互是：**玩家调好一杯酒之后，直接传送到这杯酒对应的场景。** 落日大道只是其中一种结果。调酒系统必须从一开始支持多种空间形态，不能把其他配方都做成同一条大道的换色版本。

完整流程为：**选择成分与比例 → 调酒完成 → 杯中风景展开 → 自动传送 → 探索对应内容 → 返回观星台。** 场景资源准备期间显示入境过渡和进度，并允许取消；不额外要求玩家到结果卡再点一次“进入”。配方完成只触发一次传送。重新调制已有酒杯可以重访原旅程，保留已读内容和自己的笔记。

### 第一组酒与场景的对应设计

以下十个名称沿用现有配方，场景与玩法是待制作的目标：

| 酒名 | 成分 | 对应场景 | 内容与主要动作 |
| --- | --- | --- | --- |
| 落日大道 | 文学 × 摄影 | 玫瑰色落日下的水岸长街与画廊 | 将叙事、构图与光线材料连成路线，创作摄影故事 |
| 未寄出的答案 | 文学 × 哲思 | 漂浮在黄昏中的时差邮局，不同房间通往不同选择 | 阅读书信式叙事与观点，为同一选择写出不同回答 |
| 苔藓来信 | 文学 × 自然 | 巨树根部的苔藓信林，信件藏在枝叶和树洞间 | 从植物观察与自然书写中收集细节，以另一种生命的视角创作 |
| 月光行板 | 文学 × 音乐 | 月下水上剧场，连桥通往不同乐章的舞台 | 沿节奏组织文字、情绪与叙事停顿 |
| 镜外之问 | 摄影 × 哲思 | 镜面回廊与取景庭院，从不同窗口看到同一事物 | 比较取景、省略与立场，追问画面之外的解释 |
| 露光标本 | 摄影 × 自然 | 玩家进入微观尺度的露珠花园，叶脉成为道路 | 变换远近尺度，探索形态、生长与微距表达 |
| 蓝调快门 | 摄影 × 音乐 | 蓝紫雨夜的街巷与小型演奏空间 | 根据节拍与运动挑选画面，编排一组有节奏的影像 |
| 树的时间 | 哲思 × 自然 | 环绕巨树的年轮庭园，不同枝径呈现不同季节 | 比较变化与延续、时间尺度和比喻的边界 |
| 回声悖论 | 哲思 × 音乐 | 回旋的共鸣殿堂，每次经过会出现一个可辨认的变化 | 聆听、对照，思考重复、差异与同一性 |
| 林间慢拍 | 自然 × 音乐 | 萤光湿地与风声森林，水、叶片和步道形成声景 | 观察声音来源，组合自己的自然节奏 |

各场景都绑定与配方相符的真实话题、帖子和可用媒体；进入什么地方、看到什么材料、怎样探索，应当共同体现这杯酒的成分。空间风格可以差异鲜明，同时通过木材、黄铜、玻璃、植物与统一的交互语言保持世界归属感。

成分组合决定场景家族；比例与玩家的问题改变主要视角、站点内容、灯光和探索节奏。已有旅程保存自己的版本，调整配方生成新旅程不会覆盖旧进度。酒杯是保存下来的世界入口。

### 其中一杯的完整示例：落日大道

**浪漫主义文学 × 摄影 → 落日大道**。

### 调酒到入境

1. 在星树下选两种成分：话题、收藏、文章片段或自己的想法。首个演示仍可直接用文学与摄影。
2. 调整比例。比例改变停靠点分配、主要视角与节奏，也影响酒液颜色；它不代表一个可精确测量的“思想融合度”。
3. 调制完成时，杯中出现大道的微缩倒影，画面向倒影靠近。过渡中显示“正在抵达落日大道”及加载进度；“5 站、约 10–15 分钟”是首条路线的设计目标，实际以已准备的内容为准。
4. 资源准备好后自动传送到大道入口。全过程仍可取消或返回观星台；材料或资源加载失败时保留酒杯，不将玩家留在不可操作的画面里。

### 大道本身

大道通向落日，珊瑚与紫色树冠在两侧交叠，水面映出金色天空。左侧是文学的书窗、信件和叙事片段；右侧是摄影的画框、暗房窗、构图与光线材料。两侧每一个街口共同回答一个问题。

| 站点 | 两侧材料如何连接 | 玩家要做什么 |
| --- | --- | --- |
| 1. 看见一束光 | 文学中的氛围描写 × 摄影中的光线观察 | 选择一个想表达的情绪，找到让它成立的细节 |
| 2. 画面之外 | 叙事留白 × 摄影取景与画外空间 | 比较两种取舍；说清楚省略了什么 |
| 3. 落日是否总是浪漫 | 不同文学解释 × 不同观看视角 | 阅读一组不同解释，给自己的最初判断补充一个例外 |
| 4. 让时间发生 | 叙事顺序 × 组照或连续影像 | 安排三张图或三个片段的开场、转折与结尾 |
| 5. 大道尽头 | 选过的原文依据 × 自己的观察 | 完成一份三幕摄影故事草稿，保存到小屋 |

以上是编排主题，不是假称已经检索到的文章标题。各站最终绑定真实文章、作者、出处和可用图像；模型可以生成串联问题，不能冒充作者的原话。

**不是两列互不相干的信息流。** 两侧材料之间需要有一个可回答、可比较、可实践的连接。关联不足时，路线承认“这是一组跨领域对照”，不凭空声称两个作者在互相回应。

大道允许随意停留、略过某站、深入星系或提前返回。回来后，配方杯保留旅程进度；收藏、批注和自己的草稿进入小屋。调制同一配方可以再走一遍，也可生成另一种编排，但旧旅程不被覆盖。

## 五、生成新 idea 的 API 安排

先复用现有服务端内容检索与兼容模型配置，新增独立的合成任务。现有精华功能负责准确选择原文段落；保留它的契约，不把原文提取改成自由创作。

推荐流程：**选中的个人材料 → 检索外部真实内容 → 编排候选 → 合成提案 → 校验出处 → 玩家编辑/选择 → 保存想法或进入路线。**

拟新增 `POST /api/synthesis`，区分 `idea` 和 `journey` 两种用途：

- 输入：本次主动选中的材料、一个意图、两种成分及比例、期望时长。服务器已有文章通过 source ID 取回；目前仍在浏览器的笔记，需要提交本次选择的正文，不能只发送服务端无法解析的本地 note ID。
- 想法输出：一个具体问题或假设、连接两份材料的理由、来源段落、一个反例/不确定点、一个可动手的小实验或创作提纲。
- 旅程输出：标题、环境模板、顺序站点、每站的真实材料 ID、关联理由、生成的任务与返回地点。
- 结果校验：环境只能从已经制作好的模板中选；引用 ID 必须存在，引用文字必须对应来源；不足的材料不补造；不确定的合成内容明确标为生成提案。
- 保存：保留玩家原文、模型版本与编辑后的结果，默认进入个人空间。分享只对玩家选择公开的想法或路线发生。

### API 调研结论

1. **结构化生成优先。** 服务商支持时使用 JSON Schema，结果再过服务端校验。官方 Structured Outputs 文档支持这种约束方式，但结构正确不等于推演真实。[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
2. **本地模型是备选。** Ollama 提供兼容聊天与结构化输出相关能力；可以沿用现有连接配置，具体模型效果需要另行验证。当前不假设已经安装本地模型。[Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility)
3. **语义检索随资料规模扩大再接。** 第一条路线用精选资料和现有检索即可；之后再考虑向量来寻找跨主题候选。相似度用于寻找材料，不自动证明“支持/反驳”关系。[OpenAI embeddings](https://developers.openai.com/api/docs/guides/embeddings)

首版不需要同时接多家模型、向量库和重排服务。先让一条路线的内容质量与回家沉淀成立。

## 六、四个场景共用一份内容身份

文章、段落、个人笔记、想法各有稳定 ID 与出处；书架物件、陆地阅读点和星系恒星只是不同的呈现。收藏一次即可在各处找到，批注不会因为换了场景而分叉。

旅程单独记录站点顺序、关联理由、进度与返回锚点。场景切换记录来源、位置和选中的内容：陆地展开星系之后应能回到原路口，观星台进入大道之后应能回到原酒杯旁。

每处同时提供实体入口和清晰的文字导航。文字应具体写“返回观星台”“返回大道第 2 站”或“返回小屋”；“返回上一层”仅用于星系内部层级。场景切换期间和内容加载失败时，返回功能仍然可用。

## 七、现状与实施顺序

当前实际可用：小屋、星树观星台、三级星系、星系收藏与批注、固定调酒配方。`gardenRecipes.ts` 已有“文学 × 摄影 = 落日大道”，目前仅产生名称与创作提示。小屋合成台也是本地规则文案。

当前尚未实现：可步行的落日大道、统一收藏库、模型驱动的新想法生成、无限主题陆地、第三方账户同步。现有服务使用 10 篇公开作品，模型与实时知乎搜索未配置。旧小屋、星系和配方册仍使用独立存储，下一阶段需提供可保留旧数据的统一层。

建议按一个完整体验推进：

1. **美术与空间验证**：确认本轮世界设定，先做小屋门外的水岸与可达庭园，统一窗外和观星台远景。
2. **多杯酒的传送原型**：先验证落日大道、露光标本与回声悖论三种不同空间，分别体现线性叙事、尺度观察与循环对照。每杯酒调制完成后自动抵达对应场景；同时建立稳定内容 ID、最小收藏/笔记桥接、旅程进度与返回锚点，走通调酒—入境—阅读—创作—返回小屋，不依赖任意话题生成。
3. **收获共通**：扩展到各场景的统一内容库，补齐旧数据迁移、重复内容识别与整理能力；保留已经走通的旅行闭环。
4. **接入合成服务**：先输出可靠的新问题与创作提纲，再自动编排已经验证的环境模板。
5. **扩展山林湖海与交流**：复用内容与路线系统制作其他探索方式，最后增加有真实账户与权限支持的公开路线和回应。

交付标准不是做出一张大地图，而是玩家完成一次旅行之后，能明确说出“我读了什么、理解发生了什么变化、带回了什么”。

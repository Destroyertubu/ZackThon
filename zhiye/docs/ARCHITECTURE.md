# 知野：问题驱动的三维知识探索系统

## 一、产品不是“把搜索结果摆进三维场景”

知野的核心对象是一次带着问题出发的旅程，而不是一页结果列表。推荐算法可以提供方向，但不替用户决定下一个目的地；生成能力可以帮助整理材料，但不能替用户伪造理解。产品闭环为：

```text
问题种子 → 可选择的话题方向 → 空间探索 → 阅读有来源的片段
    ↑                                      ↓
新问题 ← 新问题/观点草稿/行动实验 ← 行囊组合 + 自己的联系说明
                                            ↓
                                锚点、旅程存档、个人画布
                                            ↓
                                主动公开的路线 → 同频匹配
```

“见自己”对应私人锚点、反复经过的话题、知识组合与旅程对照；“见众生”对应经授权展示的内容和用户主动公开的不同路线；“见天地”对应允许跨界的探索方向。文学表达落实为功能，不作为未经验证的心理学效果主张。

**当前交付是完整可运行的黑客松原型工程，而不是已经接通全部官方能力或经过生产验收的成品。** 三维界面、交互、持久化和社交的本应用逻辑已实现；知乎鉴权联调、OAuth、官方素材和 GPU 路径验收仍有明确待办。

## 二、整体技术架构

```text
浏览器
 ├─ WorldView：WASD、视角、驻留、碰撞、标签投影
 │   ├─ ThreeRenderer：WebGL2 主路径
 │   └─ SoftwareRenderer：真正透视投影的软件兼容路径
 ├─ DOM 阅读/行囊/锚点/存档/隐私面板
 ├─ SVG Canvas：话题、行走轨迹、知识桥梁、地图直达
 └─ Journey State + IndexedDB 本地副本
          │  同源请求；不携带开发者 Secret
          ▼
FastAPI 应用服务
 ├─ 不透明会话 Cookie → 数据所有权检查
 ├─ World Service：种子布局、稳定扩展、节点上限
 ├─ Content Service：缓存 → 预算预留 → 合并重复请求
 │   ├─ Demo Provider：明确标记的原创演示
 │   └─ Zhihu Provider：官方 HTTP；可选已核验 CLI
 ├─ Journey Service：乐观版本号、保存、导出、删除
 └─ Sharing Service：公开白名单快照、匹配、撤回、锚点审核
          │
          ▼
SQLite / WAL
 users | worlds | journeys | anchors | reports | cache | quotas | rates
```

### 技术选型的具体责任

| 层次 | 选择 | 负责内容 | 不应承担的任务 |
| --- | --- | --- | --- |
| 三维引擎 | Three.js 0.180.0 | 相机、光照、几何、材质、实例化、后期 | 不把正文编辑塞进 WebGL 纹理 |
| 三维控制 | 独立 WorldView | 输入、模式切换、碰撞、驻留事件 | 不直接调用知乎或持有 Secret |
| 普通界面 | 原生 ESM + DOM/CSS | 中文阅读、编辑、来源链接、确认 | 不跟随每一帧重新构造所有 UI |
| 二维画布 | SVG | 可读路线、组合来源、缩放、键盘焦点 | 不把兴趣相似度包装成人格结论 |
| 服务层 | FastAPI + Pydantic | 合同校验、会话、API、持久化 | 不假装是全站抓取服务 |
| 原型存储 | SQLite/WAL | 私有记录、缓存、原子预算与修订号 | 不宣称自动跨机器扩容 |

本版没有使用 React Three Fiber、Unity 或 Babylon.js。不是认为它们不适用，而是这份原型的主要状态可以保持在一个清楚的旅程模型中，Three.js 原生控制足够。未来团队若已经熟悉 React，可迁移面板层；不要让 React 状态更新直接驱动相机的逐帧位置。

## 三、视觉与素材方案

### 3.1 美术方向：雾海里的知识群岛

统一使用低饱和青绿的空间、奶油色阅读纸面、暖金色已走路线、淡紫色知识联系。岛屿是概念区域，门环是话题辨识点，桥梁是可选择的联系。天空、岩石、植被、桥面和光点都来自本项目原创程序化几何或着色，不混搭未获授权的图片。

三层阅读距离：远处先识别话题和方向；靠近后显示少量内容片段；真正阅读和思考时切换到稳定二维面板。当前附近面板最多展示两张摘要卡，完整接口结果通过话题缓存保留，不让整个视野被文字墙遮住。

中文标签用 DOM 投影定位，最大同时显示十个，进行距离和屏幕边界过滤及重叠剔除。首页桌面标题左侧留白；手机首页隐藏三维标签，避免压住种子输入和主文案。不提供字体文件，也不依赖字体 CDN。

### 3.2 Three.js 主路径

实现位置：`web/js/renderers/three.js`。

- 合并岩石、草地、石桥等静态几何，减少碎小网格。
- 对树干及树冠使用 InstancedMesh，同一几何和材质复用；这是 Three.js 官方明确提供的减少 draw calls 的方式。
- 用 ShaderMaterial 实现渐变天空、方向性太阳光和简化水面反射/波纹；不是物理精确水体模拟。
- 使用 ACES 色调映射、SRGB 输出、半球光、方向光、可选阴影、有限泛光和输出后期。
- 重建世界时释放旧几何和材质；像素密度封顶为 1.6，轻量模式为 1。

本次无法安装 Three.js 依赖，因此这些 GPU 材质、阴影、后期与真实设备帧率**尚未执行验收**。不存在可以据此报告的“稳定 60 FPS”或“三端全兼容”测量结论。

### 3.3 软件兼容路径

实现位置：`web/js/renderers/software.js`。它不是截图，也不是把三维功能替换成平面假页面，而是共享场景数据和相机的透视三角形绘制器。WASD、投影标签、路径、收纳与面板仍然可操作；无需安装前端三维依赖即可检查闭环。

兼容路径的限制包括画家算法遮挡误差、近裁剪简化、没有真实 GPU 阴影和泛光，并且大世界下性能不如硬件渲染。这是保底方案，最终演示应在目标机器安装依赖并检查 Three.js 主路径。

### 3.4 外部素材策略

用户只提供了刘看山压缩包名称，没有可用文件或下载链接，本包未包含它们，更没有把普通动物模型称为官方刘看山。三视图是建模参考，不等于可直接用于游戏的 GLB 或动画角色。

Poly Haven 是可选的 HDRI/PBR/模型来源，其资产许可声明 CC0；但本次没有下载这些资产，也没有实现对应加载流程。当前交付的原创程序化场景已经可运行。升级应保持风格一致并记录文件来源、授权、版本和哈希，而不是把“高精度”误当作“更合适”。

## 四、问题如何生成世界

### 4.1 明确是“探索建议图”，不是权威知识图谱

World 包含 `seed`、`nodes`、`edges`、`version`、`maxNodes`。当前初始世界有七个话题区域：一个原点加六个方向。规则会根据种子选择“热爱/生活”“AI/记忆”或一般问题框架，并将种子问题与话题标题一起用于真实搜索。

这能演示问题驱动探索，但还不是基于知乎全文抽取的高质量语义图。边的 `reason` 明确写明是探索建议，不宣称两个概念存在已经被证明的因果或推导关系。

### 4.2 空间稳定性比持续重新排布更重要

节点 ID 由种子及语义路径的稳定哈希生成。初始坐标确定；扩展时只为新节点寻找不重叠位置，已有坐标不可变。用户第二次回到一座岛时，不会发现它因为新增概念而搬了家。

服务端在同一个写事务内读、扩展和更新世界，重复访问同一节点不重复产生子节点；不同访客拥有独立世界记录，不能修改对方地图。相同种子可具有相同布局，但服务器记录 ID 仍隔离。

### 4.3 扩展方向

每个可扩展话题提出三种候选方向：

| 关系 | 表达 | 例子含义 |
| --- | --- | --- |
| `deepen` | 深入一层 | 找更具体的经历、机制或证据 |
| `alternative` | 换个角度 | 寻找另一立场、反例或适用条件 |
| `bridge` | 跨界试探 | 去另一个领域提出相关问题 |

当前扩展上限为 64 节点、深度 3。不会启动无界爬取，也不会因为鼠标每帧移动就搜索。产品中的“多元路径”是交互设计机制，不能仅凭三类选项就断言已经实证突破信息茧房。

下一阶段真正语义化的做法，应由内容提供者输出带证据的候选话题，再做实体规范化、去重、多样性筛选和相关性检验；保持既有布局，不把每次 embedding 更新都反映为空间漂移。这是扩展设计，不是本版已实现功能。

## 五、第一人称交互状态机

```text
OVERVIEW：首页、输入种子、俯瞰世界
  └─ 开始 / 继续
      EXPLORING：WASD、拖拽或锁定视角
        ├─ 靠近话题 + 驻留 → 内容请求与扩图
        ├─ E → 收纳
        ├─ F / 点击卡片 → READING
        ├─ R → ANCHOR_EDITING
        ├─ B → SYNTHESIS
        └─ M → MAP
上述二维面板打开 → 解锁鼠标、清空移动状态、暂停人物
面板关闭 → 恢复探索，但不擅自重新锁定指针
```

WorldView 使用 delta-time、速度归一化和移动键集合，不把斜向移动做成额外加速。可行走范围为岛屿地面加桥梁走廊；离开范围时阻挡或尝试沿轴滑动，不让人物掉入海里。

接近阈值约 13 世界单位，离开阈值约 20；驻留超过约 0.65 秒才触发节点访问。该迟滞与驻留设计避免在边界来回抖动、频繁请求。世界单位是视觉空间单位，不是现实米数。

打开面板时人物暂停；输入框中打字不会触发 E/R 等快捷键；失焦会清空按键。地图直达与触屏按钮是替代入口，不要求每个用户承受长期第一人称行走。

## 六、内容来源与“金句”的严谨区分

Fragment 把界面文字和证据分开：`title/text/body` 是内容，`url/author/source/provenance/retrievedAt/verifiedQuote` 是来源。

当前有三种实际类型：

| 类型 | 来源 | 可以如何展示 |
| --- | --- | --- |
| `demo_original` | 项目原创示例 | 原创演示，不附虚假的知乎作者或链接 |
| `search_summary` | 官方搜索接口 | 搜索摘要，指向真实原文，不冒充逐字金句 |
| `derived` | 用户组合与说明 | 个人草稿、新问题或行动实验，不当作已证实结论 |

真实搜索没有全文时，只显示实际摘要并提供原文入口，不伪造完整文章。HTML 先清洗成纯文本；真实 URL 只接受安全的知乎 HTTPS 域名。不能将模型生成的一句话放在某位真实作者名下。

将来支持真正的原文金句，需要在已获许可的正文中核验区间，并保存内容版本、span 或校验信息；“看起来像作者说的”不是验证方法。本版没有假装存在这项全文能力。

## 七、知识行囊：从收藏到可追溯的组合

### 7.1 原始卡与派生卡必须同时存在

用户收纳时按内容 ID 去重，原卡带来源，不被组合产物覆盖。组合要求用户选择 2–4 张卡并写出自己的联系。产物类型为新问题、观点草稿或行动实验。

一个 Bridge 记录：

```text
Bridge
 id
 sourceIds[]          参与组合的卡片 ID
 targetId             新生成的派生卡
 relation             补充 / 分歧 / 类比 / 因果假设
 note                 用户写出的联系与适用条件
 createdAt
```

Derived Fragment 同样保留 `sourceIds`。下一次可以把派生卡继续参与组合，形成可追溯的来源 DAG。前端拒绝删除仍被组合引用的卡片，避免留下断裂来源。

### 7.2 没有把模板包装成 AI 推理

本版的组合是本地规则加用户说明：它将你的解释组织为一个可继续行动的结构，并附带反证或适用边界问题。没有偷偷消耗直答额度，也没有宣称调用了未接入的大模型。

例如，选择“对热爱的理解”和“刻意练习”两张卡，写下“热爱也许不是行动的前提，而会在反复实践中逐渐形成”。选择因果假设后，产物会保留这句话，并追问什么观察能够支持或推翻它；选择行动实验则加入预期、观察和反证条件。它不会把这句话改成“科学证明热爱源于练习”。

### 7.3 画布上出现真正的知识联系

画布根据来源卡的 `nodeId` 找到话题坐标；来源本身是派生卡时，递归回溯至原始话题。紫色曲线连接这些话题与一个派生节点。点击或键盘激活可看到用户的联系说明，不只是把“桥梁数 +1”。

为可读性，画布显示最近 60 条知识组合联系；全部桥梁仍保存在旅程中。本版旅程最多保存 200 条 Bridge；公开路线不包含这些私人组合说明。

## 八、个人画布与持久化

Journey 是唯一的旅程状态，包含世界 ID、修订号、当前位置和视角、访问序列、采样轨迹、行囊、锚点、知识桥梁以及开始/更新时间。

轨迹不是每帧落库：位移达到约 1.6 单位或时间间隔达到约 8 秒才加入样本；超过 2800 个样本时压缩较旧部分，同时保留起点和最新位置。后端限制最多 3000 个轨迹点。访问序列当前最多 100 项，界面“话题数”使用去重计数。

本地 IndexedDB 保存最新副本，通常通过 400 毫秒防抖写入；服务器约每十秒自动保存脏数据，也可以手动保存。页面关闭前的异步写入不能承诺绝对成功，因此演示前应手动保存并导出，不宣传零数据丢失。

服务端修订号 `revision` 用于乐观并发控制。客户端基于修订 3 保存，服务器已经是修订 4 时返回 409，不静默覆盖另一个页面的较新版本。服务器列表可继续、查看或删除旧旅程；JSON 导出用于保管完整备份，Markdown 用于阅读。**当前没有提供 JSON 文件导入界面或跨设备账号恢复**。

## 九、同频社交与锚点审核

### 9.1 同频不是偷窥完整日记

默认全部私人。只有用户主动确认，服务器才创建公开白名单投影：别名、种子问题、访问过的话题和已存在的图边。不发布连续位置、行囊、组合说明或私人锚点。

公开内容是快照，后续探索不会自动追加。更新需再次发起；撤回清空公开标识及公开快照，旧链接返回不存在。单纯知道一个 journey ID 不能读取他人的私有旅程。

### 9.2 可解释的原型匹配

当前相似度为：

$$
S(A,B)=0.65\,J(T_A,T_B)+0.35\,J(E_A,E_B),
$$

其中 $T$ 是公开话题名称集合，$E$ 是公开的有向话题图边集合，$J(X,Y)=|X\cap Y|/|X\cup Y|$；并集为空时取 0。这是候选关系图相似性，**不是连续行走路径、停留时间或访问次序的完整相似性**。

权重是原型设计参数，不是通过真实用户实验学到的最优值。界面公开共同话题、分数与算法，不据此推断年龄、心理状态或性格。

### 9.3 想法锚点分开处理

锚点可在场景中标记自己的位置并回看。选择公开后进入 `pending`，审核通过才供他人按话题查看。未经审核不会立即出现在别人的世界里。公开锚点可以举报，自己的锚点可以删除。

管理员审核目前通过受密钥保护的 API 完成，没有完整后台、机器内容审核或申诉系统。别人的公开锚点以话题阅读面板呈现，并非本版已实现跨用户实时三维坐标同步。

## 十、官方接口、缓存与限额

官方公开开发者文档确认了 HTTP 搜索地址、Bearer Access Secret 和秒级时间戳。原始 beta Skill 下载未成功，响应结构和故事/知识等能力不能凭产品介绍猜测。实时层没有取得真实密钥，故只完成适配实现和脱敏人工样本测试，没有完成官方联调。

后端缓存按查询标准化哈希存储，默认 TTL 六小时。进入话题后先检查应用缓存，未命中才预留访客预算；相同查询的并发请求加入同一个任务，上游只消耗一次开发者请求。额度在 SQLite 事务里预留并持久化，重启不会自动清零。

默认开发者搜索总预算 5000/日，来自用户给出的比赛说明；访客 80/日是自定公平预算。全网搜索、直答 Agent 未接通，不会假设它们与知乎搜索共享同一计数器。

## 十一、API 与数据模型索引

| API | 用途 |
| --- | --- |
| `POST /api/session` | 建立或恢复本应用访客会话 |
| `GET /api/health`, `GET /api/status` | 健康、数据模式、配额 |
| `POST /api/worlds`, `GET /api/worlds/{id}` | 创建种子世界、读取拥有的世界 |
| `POST /api/worlds/{id}/expand/{node}` | 原子幂等扩展 |
| `GET /api/worlds/{id}/nodes/{node}/content` | 有来源的内容 |
| `PUT/GET/DELETE /api/journeys/{id}` | 版本化保存、恢复、删除 |
| `GET /api/journeys` | 自己的存档列表 |
| `POST/DELETE /api/journeys/{id}/publish` | 明确同意后公开或撤回 |
| `GET /api/public/{slug}` | 白名单公开快照 |
| `GET /api/companions/{journey}` | 双方公开后的匹配 |
| `POST/GET /api/anchors` | 新建锚点、按话题读取可见锚点 |
| `DELETE /api/anchors/{id}` | 删除自己的锚点 |
| `POST /api/anchors/{id}/report` | 举报已公开锚点 |
| `POST /api/admin/anchors/{id}/approve` | 受管理员密钥保护的公开审核 |
| `DELETE /api/me/data` | 删除本应用全部个人数据并撤回公开记录 |

运行后可在 `/api/docs` 查阅从后端 OpenAPI 自动读取的本地接口说明，不依赖外部 CDN；`/api/openapi.json` 为同源原始契约入口。客户端不允许指定任意远端 URL 或拿前端 user ID 覆盖数据所有权。

## 十二、测试、局限与下一阶段

本次通过 10 个 JavaScript 领域测试、14 个 Python 测试；Chromium 交互检查使用软件三维、ASGI 桥接和模拟浏览器存储。此外通过了独立 Uvicorn + 真实回环 TCP 接口检查。截图是实际渲染，不是概念效果图。未测部分包括真实 GPU、真实 IndexedDB、真实网络会话部署、官方鉴权、Docker 构建及生产压力。
